# Spec — spec-002 界面与流程优化

## 背景

Phase 1（`spec-001-mvp-recording-collection`）已经交付并通过验收：员工端可以完成
「口令 → 姓名 → 录音 → 提交」，管理端可以登录、查看、试听、下载。

用户判断**核心功能已经实现，剩下的是 UI/UX 与使用流程的优化**，并于 2026-09-15
将本项决策权全权交给协调 Agent。本 Spec 把"要优化什么、优化到什么程度"
写成可验证的需求；执行中的关键取舍记录在 `.ai/decisions/008-ui-ux-polish.md`。

现状盘点（基于对 `public/` 全部代码的阅读，均为用户可感知的问题）：

**员工端**

1. 三个步骤只有卡片标题，没有全局进度感；进入录音步后无法返回修改姓名。
2. 每次都要重新输入姓名。
3. 录音时只有一行秒数，没有目标感，不知道距离目标还差多少。
4. 麦克风没采到声音时，要"录完 → 试听"才发现，白录一轮。
5. 提交进度是假的（15% → 80% → 100%），慢网络下无法判断是否在传。
6. 上传没有取消入口；网络卡住只能等服务端 60 秒超时。
7. 时长用 `Date.now()` 估算，可能与产物实际时长不一致，造成
   "前端判定够长、服务端判过短"的无谓失败（spec-001 验收报告「回归风险 3」）。
8. 有未提交录音时刷新/关闭页面，浏览器不提醒，录音直接丢。
9. 无障碍：步骤切换后焦点不动、状态变化没有 `aria-live` 播报、无 `:focus-visible` 样式。

**管理端**

10. 列表没有搜索和排序，记录变多后靠肉眼找。
11. 只能手动刷新，不知道有没有新提交。
12. 时间只有绝对时间，无法一眼看出"刚交的"。
13. 没有复制员工入口地址的入口，只能手动选中文本复制。
14. 多个播放器可以同时响。
15. 明显偏短的录音没有标记（判定阈值其实已由 `GET /api/config` 提供）。
16. 超长姓名/特殊字符的展示、100+ 条记录下的可用性未专门验证过。

## 目标

在**不改服务端接口与数据模型、不引入任何新依赖**的前提下，把两个页面的界面与
操作流程优化到"员工不需要被解释、管理员不需要翻找"的程度，并补齐可验证的
无障碍与错误处理。

## 非目标

- 不改 `server/` 与 `content/`；不新增、不修改任何 HTTP 接口与数据结构。
  实施中若发现必须改服务端，**停下来报告**，不得自行扩大范围。
- 不做员工名单、"应交/已交/未交"视图、统计汇总、音色分析（Phase 1 非目标延续）。
- 不做账号体系、SSO。
- 不做断点续传、分片上传、Service Worker / 离线缓存。
- 不做打包下载（不引入 zip 类依赖）。
- 不做暗色模式 / 主题切换。
- 不做移动端专门适配（只保证不破版、现有基础可用性不回归）。
- 不引入框架、构建步骤、CSS 预处理器；运行时依赖仍只有 `busboy`。
- 不改朗读稿与时长阈值（`content/passages.json` 保持原样）。
- 不改变"两段必须一次提交""同名覆盖"的业务规则。

## 当前行为

**员工端**：单页四区（口令 / 姓名 / 录音 / 完成），一次显示一区。录音区由 JS
按 `GET /api/config` 动态渲染两段卡片，每段有录音/停止按钮、秒数计时、试听播放器。
提交用 `fetch`，进度条为假进度。时长判定用录音过程耗时估算。

**管理端**：登录后显示一张表格（姓名 / 中文 / 英文 / 首次提交 / 最近更新），
可手动刷新、退出；每段单元格内嵌播放器与"下载 WAV"链接。无搜索、无排序、
无自动刷新、无相对时间、无复制按钮。

**共用**：`style.css` 一套朴素样式，无设计 token、无 `focus-visible`、
无响应式并排布局、无 `prefers-reduced-motion` 处理。

## 目标行为

**员工端**：顶部常驻三步指示器；姓名自动回填且可从录音步返回修改（不丢录音）；
录音时有实时计时、目标进度、输入电平，静音会得到提醒；录完时长以产物实际值为准；
提交有真实百分比、可取消、失败可重试；有未提交内容时离开会被拦截。

**管理端**：工具栏可搜索、可排序、可开关自动刷新、可复制员工入口地址；
列表显示相对时间、偏短标记；多个播放器互斥；100+ 条记录与超长姓名下依然可用。

**共用**：视觉体系统一、对比度达标、键盘可完成全流程、关键状态有屏幕阅读器播报、
窄屏不破版。所有既有安全与音频约束（口令不落前端、录音关闭后处理）保持不变。

## 功能需求

### 员工端

**E1 三步导航**

- 顶部常驻步骤指示器：`1 输口令 → 2 填姓名 → 3 录音`。当前步高亮并带
  `aria-current="step"`，已完成步骤显示完成态。
- 录音步提供"修改姓名"入口，返回第 2 步；**两段已录好的录音不丢失**，
  再次进入录音步后状态与试听保持。
- 口令校验失败（401）退回第 1 步时，姓名与录音均保留（现状已保留，本项固化为可验证要求）。

**E2 姓名记忆**

- 第 2 步姓名输入框自动填入上次成功提交/进入录音步时使用的姓名（`localStorage`）。
- **不记忆口令**：口令不得写入 `localStorage` / `sessionStorage` / URL / cookie。
- `localStorage` 不可用（隐私模式、被禁用、写入抛错）时静默降级，不影响任何流程。

**E3 录音界面信息与布局**

- 每段卡片显示：语言标签、状态徽标（未录音 / 录音中 / 已录制 X 秒）、
  目标时长提示（约 N 秒）、朗读稿。
- 视口宽度 ≥ 900px 时两段并排（一行两列）；< 900px 时单列堆叠。
- 开始录音后页面滚动到该段并高亮；正在录制的段落有明确的进行中视觉。

**E4 计时与进度**

- 录音时显示实时计时（0.1 秒精度）与目标进度条；进度条需能区分
  `minSeconds`（下限）、`targetSeconds`（目标）、`maxSeconds`（上限）三个刻度。
- 到达 `targetSeconds` 时显示"已录满，可以停止"的正向提示，**不自动停止**。
- 到达 `maxSeconds` 自动停止录音（现状行为必须保持）。
- 计时数字每 200ms 的刷新**不得**进入 `aria-live` 播报；对
  "开始录音 / 到达目标 / 自动停止 / 录音完成 / 录音失败"做 polite 播报。

**E5 音量电平与静音提示（非侵入）**

- 录音过程中显示实时输入电平（音量条）。
- 连续 **3 秒**电平接近静音（RMS 低于实现常量，默认取 0.01）时，显示
  "没有检测到声音，请检查麦克风"的提示；**不打断录音、不自动停止**。
- 电平分析**不得改变录音数据**：`getUserMedia` 的 `echoCancellation` /
  `noiseSuppression` / `autoGainControl` 仍必须为 `false`，不得为录音流新增约束。
- `AudioContext` / `AnalyserNode` 不可用、创建失败或被浏览器挂起时，
  隐藏电平条与静音提示，其余功能不受影响。

**E6 时长判定以实际产物为准**

- 录音结束后，以产物 Blob 的实际可读时长作为该段时长（通过 `Audio` 元素读取元数据）。
- 元数据不可读（拿不到有限时长）时，回退为录音过程耗时估算，行为与现状一致。
- 是否短于 `minSeconds` 用该实际时长判定，提交前阻止并提示；不得再出现
  "前端判定够长、服务端 400 判过短"的常规路径。

**E7 试听与重录**

- 每段独立试听、独立重录；重录覆盖该段旧产物。
- 同一时刻只允许一段处于录音状态（现状保持）；试听不占用麦克风。

**E8 提交：真实进度、可取消、失败可重试**

- 上传进度显示真实百分比（`XMLHttpRequest.upload` 的 `progress` 事件）；
  浏览器不提供进度事件时显示"上传中"，不假装百分比。
- 上传过程中提供"取消上传"；取消后两段录音保留、回到可提交状态，
  并显示"已取消上传"的可读提示。
- 提交失败（网络错误 / 400 / 401 / 408 / 413 / 500）保留录音，
  错误就地显示，按钮变为可再次点击的"重试提交"。
- 提交成功后显示摘要：姓名、两段时长、提交时间，并提供
  "重新录制并再次提交"入口（覆盖语义不变）。
- 401（口令失效）仍退回第 1 步，且保留姓名与录音。

**E9 离开保护**

- 存在已录制但未提交的内容、或正在上传时，刷新/关闭/导航离开触发浏览器确认。
- 没有未提交内容时不打扰。

### 管理端

**A1 工具栏：搜索与排序**

- 搜索框按姓名实时过滤（子串匹配、大小写不敏感）；过滤后计数显示
  "显示 X / 共 Y 条"。
- 排序选择：最近更新（默认，倒序）/ 首次提交（倒序）/ 姓名（升序，
  按 `localeCompare('zh-CN')`）。
- 以上均为纯前端操作，不新增接口。

**A2 自动刷新**

- 默认开启，间隔 **30 秒**拉取一次列表；`document.hidden` 时暂停，
  重新可见时立即刷新一次。
- 提供开关可关闭自动刷新；工具栏显示"最后刷新时间"，开启时显示距下次刷新的提示。
- 刷新失败**不清空已有列表**，显示错误提示；会话失效（401）停止轮询并回到登录态。

**A3 列表呈现**

- 时长低于 `minSeconds` 的录音标记"偏短"（阈值来自公开接口 `GET /api/config`；
  该请求失败则不做标记，不阻塞列表显示）。
- 时间显示相对格式（刚刚 / X 分钟前 / X 小时前 / X 天前）+ `title` 精确时间；
  相对时间每分钟自动更新，不重新拉取列表。
- 工具栏与空状态均提供"复制员工入口地址"按钮；复制成功显示"已复制"；
  剪贴板不可用时给出降级提示（展示可手动复制的文本）。

**A4 试听互斥**

- 开始播放某段时，自动暂停其他正在播放的播放器。

**A5 稳健展示**

- 超长姓名（≥50 字符）不破版、不遮挡操作；姓名仍必须用 `textContent` 渲染，
  XSS 不得回归。
- 100 条记录下，列表渲染与搜索输入无可感知卡顿（搜索输入到列表更新的
  响应 < 200ms）。

### 通用

**U1 视觉与排版**

- 统一设计 token（颜色 / 间距 / 圆角 / 字号 / 阴影）；主按钮、次按钮、
  危险操作层级清晰；禁用态与进行中状态明确。
- 正文文字与按钮文字对比度 ≥ 4.5:1。
- 朗读稿排版：可读行宽、舒适行高、与操作区视觉分离。

**U2 响应式**

- 员工端与 E3 一致；管理端窄屏下表格横向滚动、工具栏换行不重叠。
- 不为移动端新增专门交互。

**U3 无障碍与键盘**

- 所有交互控件可仅用键盘完成；每次步骤切换后焦点移动到该步标题
  （`tabindex="-1"` + `focus()`）。
- 全局错误、提交结果、录音关键状态变化用 `aria-live="polite"` 播报。
- 可见的 `:focus-visible` 样式；动画/过渡遵循 `prefers-reduced-motion`。

**U4 约束遵守（回归）**

- 不新增运行时依赖、不新增构建步骤、不使用框架。
- 前端仍为零构建静态资源，文件继续放在 `public/`。
- 录音约束（EC/NS/AGC 全关）与口令安全约束（只在服务端校验、前端不持久化）不变。

## 边界条件

- `localStorage` 被禁用或写入抛错 → 静默降级（E2）。
- 剪贴板 API 不可用或非 secure context → 复制按钮给出降级提示（A3）。
- `AudioContext` 创建失败 / 被挂起 → 电平条隐藏，不出现报错循环（E5）。
- 录音中途 `MediaRecorder` 报错 → 丢弃该段并给出可读提示，回到未录音态（现状保持）。
- 上传中取消 / 断网 / 服务端 408 → 录音保留、可重试；服务端 `data/tmp/`
  不得留下半截文件（spec-001 既有保证，本 spec 必须回归验证）。
- 上传中用户刷新页面 → `beforeunload` 拦截（E9）。
- 管理端列表 0 条 / 1 条 / 100+ 条；姓名含 emoji、HTML 标签、超长字符串。
- 自动刷新轮询收到 401 → 停止轮询、回登录态（A2）。
- 页面停在录音步被刷新 → 回第 1 步（内存 Blob 无法保留）；刷新前已有 E9 拦截。
- 时间字段缺失或非法 → 显示"—"（现状保持）。
- 两段录音时长同时通过校验但姓名超长 → 提交仍按服务端规则处理，前端不得新增限制。

## 技术约束

- 遵循 `constitution/tech-stack.md`；本 Spec 为**纯前端改动**（`public/` 内），
  服务端与数据模型不变。
- 不引入依赖；不使用打包器；CSS 手写。
- 目标浏览器：Chrome / Edge / Safari 近期版本；Safari 的 `audio/mp4`
  录音分支必须保持可用。
- 验证方式：本机 `npm start` + 浏览器自动化（Playwright/Chromium，
  fake device）覆盖可自动化部分；真麦克风录制手感与音质由用户手工确认（不变）。

## 兼容性要求

- `data/` 既有索引与录音无需迁移，管理端对既有记录的展示不变。
- 既有接口与错误语义不变；不得因前端改用 XHR 而改变 401 / 408 / 413 / 500
  的处理结果。
- 静态资源缓存策略保持 `no-cache` 现状，不引入 Service Worker。

## 验收标准

- [ ] 步骤指示器在三个步骤中正确高亮与标记完成；从录音步"修改姓名"返回再回来，两段已录录音仍可试听、可提交（实测）
- [ ] 姓名在第二次进入时自动回填；清除 `localStorage` / 隐私模式下页面不报错、流程可用
- [ ] 录音时可见实时计时与目标进度；到达 target 显示正向提示；到达 max 自动停止（临时调小阈值后实测，测完还原 `passages.json`）
- [ ] 录音时电平条随声音变化；静音 3 秒出现提示且录音未被中断；Web Audio 不可用时无报错
- [ ] 录音结束后显示的时长与产物实际时长一致（已知长度样本，误差 ≤ 0.5 秒）；不再出现"前端够长、服务端 400"
- [ ] 两段录音在 ≥900px 视口并排、窄视口单列；窄屏无横向溢出（管理端表格滚动区除外）
- [ ] 上传显示真实百分比；"取消上传"可中止，录音保留、提示可读、可重新提交；服务端 `data/tmp/` 与 fd 无残留（复跑 spec-001 Tests A 场景）
- [ ] 提交失败（模拟断网 / 500 / 408）后按钮变为"重试提交"，重试成功且数据正确落盘
- [ ] 有未提交录音时刷新触发浏览器确认；无录音时不触发
- [ ] 管理端搜索按姓名子串过滤、大小写不敏感；计数显示"显示 X / 共 Y 条"
- [ ] 管理端三种排序均生效；中文姓名排序稳定
- [ ] 自动刷新默认开启且按 30 秒节奏请求（观察网络请求）；切后台暂停、回前台立即刷新；关闭开关后不再轮询
- [ ] 时长低于 `minSeconds` 的记录显示"偏短"；`/api/config` 不可用时列表照常显示
- [ ] 相对时间显示正确并随时间更新；`title` 为精确时间
- [ ] "复制员工入口地址"在 localhost/https 下复制成功并提示；剪贴板不可用时有降级提示
- [ ] 播放一段音频时其他播放器自动暂停（实测至少两个播放器）
- [ ] 100 条记录下列表可用，搜索响应 < 200ms
- [ ] 姓名含 `<img src=x onerror=...>`、超长字符串时管理端不执行脚本、不破版
- [ ] 键盘可完成员工端全流程；步骤切换后焦点落在该步标题；关键状态变化有 `aria-live` 播报节点
- [ ] 存在可见 `:focus-visible` 样式；`prefers-reduced-motion` 下无强动效
- [ ] 正文与按钮文字对比度 ≥ 4.5:1（抽查计算）
- [ ] 加载与全流程操作中控制台无未捕获错误
- [ ] `package.json` 无新增依赖（运行时仍只有 busboy）；根目录结构未变
- [ ] `README.md` 描述与新增能力一致；`specs/README.md` 已登记 spec-002
