# Spec — spec-003 界面重设计（视觉与排版）

## 背景

`recording` 的功能（spec-001）与流程体验（spec-002）已经交付并通过验收，但**视觉层**
从未被系统性设计过：样式是在功能实现中逐步堆出来的，用户判断"太丑、排版不整齐、没有结构"。

本次任务由用户发起，并明确允许：**截图识别当前 UI**、**联网参考同类产品**。
现状盘点基于 11 张实拍截图（1440 / 1280 / 1024 / 390 宽，覆盖员工端与
管理端的空闲、录音中、已录、完成、登录、列表等状态），逐条列出可核查的问题。

外部参考（已实际查阅）：

| 参考 | 借鉴点 |
|---|---|
| [Online Voice Recorder (123apps)](https://online-voice-recorder.com/) | 录音视图只保留**一个主导控件 + 大号计时**，其余全部次级化 |
| [NN/g: Wizards](https://www.nngroup.com/articles/wizards/) | 步骤器要在页面上明确列出全部步骤、突出当前步、顺序不可跳、按钮文案要说明下一步做什么 |
| [NN/g: Visual Hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | 层级靠颜色对比、尺寸（最多 3 级）、间距分组表达；"全都强调等于都不强调" |
| [shadcn/ui Data Table](https://ui.shadcn.com/docs/components/data-table) | 工具栏与表格分离、搜索置于表格上方、状态用徽标、空态统一样式、行操作收敛 |

## 目标

在不改变任何业务行为、不新增依赖、不动 `server/` 的前提下，把员工端与管理端
重做成**结构清楚、对齐整齐、层级分明**的现代内部工具，并产出可逐屏复核的
截图证据（before / after）。

## 非目标

- 不改功能行为、接口、数据模型、错误语义；`server/` 与 `content/` 一律不动。
- 不引入框架、构建工具、CSS 预处理器、UI 库、图标库、webfont。
- 不做暗色模式、主题切换；不做营销页式装饰与插画。
- 不做移动端专门适配（沿用 mission 的非目标），只保证不破版。
- 不改动朗读稿、时长阈值、安全与音频约束（EC/NS/AGC 等）。

## 当前行为（现状盘点，附证据）

**全局**

1. **页脚不贴底**：内容不足一屏时页脚停在中部，下方大片空白（截图 01/07/09）。
   根因是页面没有 `min-height: 100vh` 的纵向骨架。
2. **没有页面骨架与栅格**：顶栏是全宽白条，主容器 `max-width: 1080` 之后全靠
   零散 margin 拼；间距值混杂（10/12/16/18/20/24px），无统一节奏。
3. **层级靠边框而非对比**：几乎一切都是"带边框 + 阴影的卡片"，
   主要动作（提交）与次要信息（提示文字）重量接近。
4. **字号只有 3 档且差距过小**（22/17/16），正文与提示文字颜色、字重区分不足；
   数字（计时、时长）未使用等宽数字，跳动时左右晃。

**员工端**

5. **序号重复**：步骤指示器已标 1/2/3，卡片标题又写一遍"1 输入员工口令"。
6. **录音页两卡高度不齐**：中英文文稿长度不同 → 卡片底边一高一低
   （截图 03：左卡底 ≈780px、右卡底 ≈830px），并排观看"参差"。
7. **卡头过挤**：语言名 + 状态胶囊 + "目标约 60 秒 · 最少 10 秒 · 最长 180 秒"
   挤在同一行，两卡重复同一段目标文案。
8. **录音区像调试面板**：进度条、进度文字、电平条、两个按钮、计时各自成行
   堆叠；主导控件（开始/停止录音）不突出，录音中"停止"与"录音中"两个按钮
   同时占位（截图 04）。
9. **提交区不成立**：一条通栏横幅 + 居中按钮，禁用时仍是蓝色主按钮外观
   （低对比、像坏了），"还需要：……"的小字说明埋在下面（截图 03）。
10. **完成页空旷**：通栏卡片里放一行摘要，左右大量空白（截图 07）。

**管理端**

11. **工具栏无分组**：计数、搜索、排序、自动刷新复选框、三个按钮排成一行，
    七个控件视觉权重相同；390 宽时折成三行且搜索独占一行（截图 09/10）。
12. **表格被原生播放器统治**：每行两个浏览器默认 `audio` 控件；
    8 条记录行高 ≈137px，1440×900 只能看到 6 行多；"下载 WAV" 再占一行，
    行内纵向留白远大于信息量。
13. **列宽与对齐随意**：姓名列窄、两段录音列吃掉大部分宽度；时间列左对齐；
    长姓名换行会把行撑高。
14. **状态表达弱**："偏短"徽标与时长混在一句话里，不易扫读。

## 目标行为

**员工端**：页面有明确骨架（顶栏 / 主区 / 贴底页脚）；步骤器是唯一的进度来源；
录音工作区的两张卡片底边对齐、控件分组固定；每段的"开始/停止"是明确的主行动，
计时与目标进度一眼可读；提交区是一个正式的"最后一步"，可用/不可用状态一目了然；
完成页聚焦且不空旷。整体观感：干净、克制、安静，不需要向员工解释任何视觉隐喻。

**管理端**：顶部是"标题 + 统计 + 分组控件"的单行工具栏（窄屏有序折行）；
表格行高显著收紧，录音用自研精简播放器（播放/暂停 + 进度 + 时长），下载收敛为
图标按钮；姓名、时长、时间三列对齐规范；**8 条记录在 1440×900 内可见 ≥7 行**。
整体观感：信息密度像 Linear / Stripe 的后台，而不是表单拼盘。

## 功能需求

### 全局

**V1 页面骨架与页脚**

- `body` 采用纵向 flex 骨架（`min-height: 100vh`），页脚永远贴住视口底部
  （内容不足一屏时也不例外）；内容超出一屏时正常跟随滚动。
- 顶栏、主区、页脚使用**同一套水平内边距**，1440 宽下左右边距一致。

**V2 设计 token**

- 全部颜色、字号、间距、圆角、阴影、层级收敛为一组 CSS 变量（`:root`），
  页面样式只引用变量，不出现散落的硬编码色值/间距（以代码抽查为准）。
- 间距采用 4px 基数（4/8/12/16/24/32/48）；字号不超过 3 级主层级
  （正文 / 小标题 / 页标题），配合 2 种字重（400/600）。
- 计时、时长、计数等数字使用 `font-variant-numeric: tabular-nums`。

**V3 按钮与行动层级**

- 定义三种按钮：主按钮（实心强调色）、次按钮（描边）、文字按钮（链接式）。
- **单个卡片内最多 1 个主按钮**；任何禁用状态不得再呈现"实心主按钮"外观
  （用次级外观 + 明确的不可用说明）。
- 悬停、按下、聚焦、禁用、加载五种状态在两种页面上表现一致。

**V4 顶栏**

- 员工端与管理端有统一顶栏：产品名 + 端别标识 + 一句话说明。
- 两页视觉同源，但通过端别标识与标题清晰区分身份。

**V5 步骤指示器**

- 步骤器是**页面上唯一的步骤编号来源**；卡片标题不再重复序号。
- 三态表达：已完成（对勾）、当前（强调 + 加粗）、未开始（弱化）；
  步骤之间用连接线/箭头分隔；当前步带 `aria-current="step"`（沿用 spec-002）。

### 员工端

**V6 录音工作区布局**

- ≥1024px：两段录音卡片并排，**底边严格对齐**（同一行的卡片等高）。
- 文稿区高度统一（超长文稿在区内滚动），保证两卡的操作区处于同一水平线。
- 控制区固定在卡片底部：主按钮 + 计时 + 目标进度 + 电平，分组紧凑，
  不再是"每样一行"的堆叠。
- <1024px 单列堆叠。

**V7 录音状态可视化**

- 录音中：卡片有明确的进行中标识（强调边框 + "录音中"徽标 + 动态指示），
  计时放大为主视觉；开始按钮隐藏或替换为"停止"主行动，不再两个按钮同时占位。
- 目标进度条上标出最短/目标刻度，并在接近/达到目标时改变状态色与文案
  （沿用 spec-002 的到达目标提示、到上限自动停止逻辑）。
- 电平条作为录音中的辅助信息，融入控制区，不单独占一行；静音提示保持（spec-002）。

**V8 提交区**

- 提交区是独立的"最后一步"区块：显示两段摘要（时长 + 状态）、缺失项说明、
  提交按钮与上传进度（含取消/重试，沿用 spec-002 行为）。
- 不可提交时按钮为次级外观并说明"还需要什么"；可提交时为唯一主按钮。

**V9 完成页**

- 聚焦式成功布局（居中的收束宽度），摘要用清晰的定义列表呈现；
  提供"重新录制"次按钮与返回说明，不再是一张空旷的通栏卡片。

### 管理端

**V10 工具栏**

- 一行式结构，内部按功能分组：左侧标题 + 统计/刷新状态；右侧
  「筛选（搜索 + 排序）｜ 设置（自动刷新开关）｜ 操作（复制入口 / 刷新 / 退出）」。
- 搜索框带图标；自动刷新用开关控件（不是裸复选框）；操作按钮区分主次
  （刷新为主，复制/退出为次级）。
- <768px 时按组折行，搜索独占一行占满宽度，禁止出现参差折行。

**V11 表格**

- 行高收紧：8 条记录在 1440×900 视口内可见 ≥7 行（行高含内边距 ≤96px）。
- **自研精简播放器**替换原生 `audio` 控件（不引依赖、不使用 JS 音频解码）：
  - 播放/暂停按钮（`<button>`，含 `aria-label`）、可拖动/可键盘调节的进度条
    （原生 `input[type=range]` 或等价可聚焦控件）、`已播 / 总时长` 文本；
  - 键盘可操作：聚焦后用空格/回车切换播放，方向键调节进度；
  - 播放互斥沿用 spec-002（开始一段时暂停其他）。
- 下载收敛为图标按钮（带 `aria-label` 与 `title`），不再独占一行。
- 姓名、时长列左对齐规范，时间列右对齐；表头吸顶；行有 hover 反馈；
  长姓名不再撑高行（截断 + `title` 显示全名）。
- 时长统一格式 `m:ss.s`（如 `1:02.4`），"偏短"用徽标紧邻时长显示。

**V12 图标**

- 内联 SVG 图标集（至少：麦克风、停止、播放、暂停、下载、搜索、刷新、
  复制、对勾、警示），统一尺寸（20px 视口，可缩）、描边宽度与 `currentColor`；
  不引入图标库、不使用 emoji 作为功能图标。

**V13 空态与反馈**

- 空列表、复制成功、错误、上传中等反馈使用统一组件样式；
  文案风格与 spec-002 一致（可读、说明怎么办）。

### 通用约束

**V14 既有可用性与无障碍不回退**

- spec-002 的全部约束继续成立：对比度 ≥4.5:1、`:focus-visible` 可见、
  关键状态 `aria-live` 播报、`prefers-reduced-motion` 下无强动效、
  键盘可完成员工端全流程、录音 EC/NS/AGC 全关。
- 自研播放器等新控件必须可键盘操作且有可读的无障碍名称。

**V15 响应式**

- 固定检查点：1440 / 1280 / 1024 / 768 / 390。
- 任何检查点都不得出现**页面级**横向滚动（表格允许在自身容器内滚动）；
  员工端 <1024 单列；窄屏下按钮/开关的触控目标 ≥40px。

**V16 一致性**

- 两页共享同一 token 与组件样式；同类元素（按钮、徽标、提示、输入框）
  在两页外观一致。

## 边界条件

- 超长中文姓名（≥50 字符）、含 HTML 的姓名：表格不破版、不撑高行（XSS 约束不变）。
- 0 条 / 1 条 / 8 条 / 100+ 条记录：空态、紧凑表格、100 条下搜索仍 <200ms（spec-002）。
- 0 秒 / 极短（<minSeconds）/ 正常 / 接近上限的录音：状态色与文案正确切换。
- 上传中 / 取消 / 失败重试 / 已完成的提交区状态。
- 空闲 / 录音中 / 已录 / 播放中的段落卡片状态。
- 视口 390 宽：工具栏折行整齐、表格容器内滚动、无页面级横滚。
- 系统字体回退路径（不加载 webfont）。
- 禁用态、hover 态、focus 态在浅色主题下的对比度。

## 技术约束

- 只改 `public/` 下的 HTML / CSS / JS 与必要的文档；`server/`、`content/` 不动。
- 零构建、无运行时依赖（`package.json` 不变）；图标用内联 SVG `symbol` 复用。
- 允许使用现代 CSS（grid、flex、`clamp()`、自定义属性）；目标浏览器为
  Chrome / Edge / Safari 近期版本，不做旧浏览器回退。
- DOM 语义角色不变（按钮仍是 `button`，输入仍是 `input`）；自研播放器使用
  标准可聚焦控件而不是 `div` 模拟。
- 不引入图片/字体等额外静态资源；SVG 内联在 HTML 或由 JS 以内联字符串注入
  （同一来源，不额外请求）。
- 保留 spec-002 的所有行为与错误路径；本次改动不得改变任何接口调用。

## 兼容性要求

- 既有 `data/`（索引与录音）无需迁移，展示结构不变。
- 与 spec-002 的行为兼容：同一套交互流程与快捷键不退化。
- 不使用仅在某一浏览器可用的实验特性；`input[type=range]` 样式需在
  Chrome / Safari 下均可接受（自定义样式时保留可拖动性）。

## 验收标准

- [ ] **页脚贴底**：内容不足一屏时，页面总高 = 视口高，页脚底边贴住视口底（±1px）；内容超一屏正常滚动
- [ ] **两卡等高**：1440×900 员工端录音页，两段卡片底边高度差 ≤1px；1024 宽同样成立
- [ ] **步骤序号不重复**：页面上只有步骤器带序号，卡片标题无"1/2/3"前缀
- [ ] **单卡一个主按钮**：任一状态下，单张卡片内实心主按钮 ≤1；禁用态不是实心外观
- [ ] **工具栏分组**：1440 宽一行排布，搜索/排序/开关/操作三组可辨识；390 宽折行无参差、搜索占满一行
- [ ] **表格密度**：1440×900、8 条记录时可见行数 ≥7（行高 ≤96px）
- [ ] **自研播放器**：键盘可达（空格/回车播放暂停、方向键调节进度）、有 aria-label、播放互斥仍成立、时间显示 `m:ss.s`
- [ ] **下载与时间对齐**：下载为图标按钮；时间列右对齐；姓名过长不撑高行（截断 + title）
- [ ] **图标统一**：功能图标全部为内联 SVG，无 emoji/unicode 符号充当图标（步骤完成勾选除外，且也应为 SVG/CSS 绘制）
- [ ] **响应式**：1440/1280/1024/768/390 五档均无页面级横向滚动（`docScrollWidth ≤ innerWidth+1`）；员工端 <1024 单列
- [ ] **对比度**：抽查 ≥10 组新 token 组合，正文/按钮文字 ≥4.5:1；禁用态有可读性说明
- [ ] **无障碍不回退**：焦点仍落在步骤标题、`:focus-visible` 可见、`aria-live` 节点存在、reduced-motion 下无强动效、键盘可完成全流程
- [ ] **spec-002 关键回归**：录音约束 EC/NS/AGC 全关；上传真实进度/取消/重试；beforeunload；搜索/排序/自动刷新；XSS 姓名纯文本；100 条搜索 <200ms
- [ ] **无新增依赖**：`package.json` / lockfile 不变；无新增静态资源请求（Network 面板核对）
- [ ] **截图证据**：1440/1280/1024/768/390 × 员工端（口令/姓名/录音空闲/录音中/已录/完成）与管理端（登录/列表/空态）逐屏留存 before/after
- [ ] **控制台**：加载与全流程操作无未捕获错误
- [ ] **文档同步**：`specs/README.md` 登记 spec-003；README 若有界面描述需一致

## 待确认问题

1. **设计方向偏好**：默认取"干净、克制的专业工具感"（中性灰阶 + 单一强调色，
   接近 Linear / Stripe 后台）。备选：更柔和（大圆角、浅色调）或更强的品牌感
   （品牌色 + 空态插画）。以用户选择为准。
2. **桌面端录音区布局**：默认两列等高（两段同时可见、便于对照）；
   备选是单列"一次只做一段"的向导式布局（更聚焦但多一次切换）。
3. **"偏短"等状态色**是否保留现有语义色（黄/绿/红）——默认保留。
