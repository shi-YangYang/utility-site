# Spec — spec-001 MVP 录音收集

## 背景

公司需要采集员工的中英文语音样本用于下游音色分析，目前靠线下收文件，收不齐、格式乱、
不知道谁没交。需要一个内部网页工具把"朗读 → 录音 → 提交 → 汇总查看"这条链路跑通。

本 Spec 是 `recording` 子项目的第一个 Spec，覆盖 Phase 1（MVP）的全部范围。

## 目标

让员工能在浏览器里完成"输口令 → 填姓名 → 录中文、英文各一段 → 提交"，
让管理员能在浏览器里看到全部提交记录并试听、下载。
服务端把上传音频统一转成规整的 WAV 落盘，一人一条最新记录。

## 非目标

- 不做音色分析、说话人识别、语音转写、质量评分。
- 不做账号体系、不做员工名单、"应交/已交/未交"视图、不做统计汇总。
- 不做 HTTPS 部署，不做 CI 配置（两者都属于后续阶段，见 `constitution/tech-stack.md` 待确认项）。
- 不做移动端专门适配。
- 不做断点续传、不做分片上传、不做并发多人同时同一姓名的冲突合并策略（按后到覆盖处理）。

## 当前行为

无。本项目为新建，仓库中此前不存在 `recording/`。

## 目标行为

**员工端**（`/`）：

打开页面先要求输入员工端口令。口令正确后出现姓名输入框。填完姓名进入录音界面，
页面展示两段朗读文稿（中文一段、英文一段），每段各有一个录音按钮、计时显示、
试听播放器和重录按钮。两段都录好后"提交"按钮才可用。提交成功后页面显示成功状态
和已提交的姓名，并提供"重新录制并再次提交"的入口。

**管理端**（`/admin.html`）：

打开页面先要求输入管理端口令。正确后展示提交列表：每行一个员工，列出姓名、
中文录音（时长 + 试听 + 下载）、英文录音（时长 + 试听 + 下载）、首次提交时间、最近更新时间。
页面提供手动刷新。没有提交时显示空状态提示。

**服务端**：

接收员工提交的音频，校验口令与姓名，用 ffmpeg 转成单声道 16-bit PCM WAV，
写入数据目录并更新员工索引。同名提交覆盖旧录音。

## 功能需求

### F1 公开配置接口

`GET /api/config`

返回前端渲染所需的全部公开配置，**不得包含任何口令**：

```json
{
  "targetSeconds": 60,
  "minSeconds": 10,
  "maxSeconds": 180,
  "maxUploadMb": 50,
  "segments": [
    { "key": "zh", "label": "中文", "lang": "zh-CN", "text": "<中文朗读稿>" },
    { "key": "en", "label": "英文", "lang": "en-US", "text": "<英文朗读稿>" }
  ]
}
```

数据来源为 `content/passages.json`；`maxUploadMb` 来自环境变量。

### F2 员工端口令校验

`POST /api/employee/access`，请求体 `{"code":"..."}`

- 正确 → `200 {"ok":true}`
- 错误 → `401 {"ok":false,"error":"口令不正确"}`

此接口仅用于前端放行界面。**真正的安全边界在 F4**：提交接口会再校验一次口令，
绕过前端直接调用提交接口不会得到任何特权。

### F3 静态页面

- `GET /` → 员工端页面
- `GET /admin.html` → 管理端页面
- 前端静态资源（js / css）可被正常访问

静态资源不得泄露 `server/`、`content/` 之外的服务端源码，不得目录穿越。

### F4 提交录音

`POST /api/submit`，`multipart/form-data`

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | 文本 | 员工端口令 |
| `name` | 文本 | 员工姓名（用户输入，不可信） |
| `zh` | 文件 | 中文录音 |
| `en` | 文件 | 英文录音 |

成功：

```json
{ "ok": true, "name": "张三", "updatedAt": "2026-09-15T08:05:00.000Z" }
```

失败（均为 JSON，含 `error` 字段说明原因）：

| 状态码 | 场景 |
|---|---|
| `400` | 缺姓名、姓名为空、缺任一段音频、音频为空文件 |
| `401` | 员工端口令错误 |
| `413` | 单个文件超过 `MAX_UPLOAD_MB` |
| `415` | 文件类型明显不是音频（可选，允许宽松判断） |
| `408` | 上传超时：连接空闲超过 30 秒，或请求体接收阶段超过 60 秒 |
| `500` | ffmpeg 转码失败或写盘失败 |

> `408` 是本条在本 Spec 初版未定义、于第一轮返工时补入的：初版只描述了"超时不得留下
> 半截文件"，没有规定超时该回什么状态码。实施时选择了 `408 Request Timeout`，
> 与 Node 自身 `server.requestTimeout` 的行为一致。仅在后端接收请求体阶段生效；
> 请求体接收完毕后进入转码/落盘阶段时不再受此限制。

两段音频必须**同时提交**（一次请求带两个文件）；只交一段视为 `400`。

### F5 管理端登录

`POST /api/admin/login`，请求体 `{"code":"..."}`

- 正确 → `200 {"ok":true}`，并下发 `httpOnly` + `SameSite=Strict` 的会话 cookie
- 错误 → `401 {"ok":false,"error":"口令不正确"}`

`POST /api/admin/logout` 清除会话。

`GET /api/admin/session` 返回当前会话是否有效，供管理页判断是否需要重新登录。

### F6 提交列表

`GET /api/admin/submissions`（需管理端会话）

```json
{
  "employees": [
    {
      "id": "<服务端生成的稳定 id>",
      "name": "张三",
      "firstSubmittedAt": "2026-09-15T08:00:00.000Z",
      "updatedAt": "2026-09-15T08:05:00.000Z",
      "segments": {
        "zh": { "durationSec": 61.2, "bytes": 1960000,
                "audioUrl": "/api/admin/audio/<id>/zh",
                "downloadUrl": "/api/admin/download/<id>/zh" },
        "en": { "durationSec": 58.4, "bytes": 1870000,
                "audioUrl": "/api/admin/audio/<id>/en",
                "downloadUrl": "/api/admin/download/<id>/en" }
      }
    }
  ]
}
```

未鉴权 → `401`。列表按 `updatedAt` 倒序（最近提交的排在前面）。

### F7 音频试听

`GET /api/admin/audio/:id/:segment`（需管理端会话）

以 `audio/wav` 流式返回。需支持 HTTP `Range` 请求，保证前端播放器可以拖动进度条。
未鉴权 → `401`；员工或段落不存在 → `404`。

### F8 音频下载

`GET /api/admin/download/:id/:segment`（需管理端会话）

与 F7 相同的数据，但带 `Content-Disposition: attachment`，
文件名形如 `<姓名>-zh.wav`（中文名需正确处理 `filename*` 编码）。
未鉴权 → `401`。

### F9 转码

每次提交的音频经 ffmpeg 转为：**单声道、16-bit PCM、采样率 `SAMPLE_RATE`（默认 16000 Hz）的 WAV**。

- 采样率、声道数从环境变量/常量读取，不硬编码在多处。
- 转码结果需校验：文件非空，且能被 ffprobe 读出的时长与预期量级一致。
- 转码失败必须让整个提交失败并返回 `500`，**不得**留下半截文件或写入索引。

### F10 存储与索引

- 录音：`DATA_DIR/recordings/<id>/zh.wav`、`en.wav`、`meta.json`
- 索引：`DATA_DIR/index.json`，记录每个员工的姓名、id、提交时间、两段音频的元信息
- 同名提交覆盖：同一个姓名再次提交，覆盖 `zh.wav` / `en.wav`，
  保留 `firstSubmittedAt`，更新 `updatedAt`
- 索引写入必须原子（临时文件 + rename）
- 并发提交必须串行化，不得出现索引损坏或互相覆盖写
- `DATA_DIR` 不存在时服务启动自动创建

### F11 启动自检

服务启动时必须：

1. 检测 ffmpeg 可用（能执行并返回版本）。不可用则**启动失败退出**，打印明确的中文提示，
   说明如何安装。
2. 打印监听地址、两个入口的 URL、数据目录路径。
3. 若 `ADMIN_CODE` 仍是默认值，打印醒目警告，提示上线前必须修改。

## 边界条件

- **姓名不可信**：用作路径前必须消毒——剥离 `/`、`\`、`..`、控制字符、前导点，
  去除首尾空白，限制长度。消毒后为空或不可用时，回退为基于原始姓名的 hash 目录名。
  显示名始终保留用户原始输入（去首尾空白后），存在索引里。
- **姓名消毒后撞车**：两个不同的原始姓名消毒后得到同一个目录名时，
  后到的那个追加短 hash 后缀，避免互相覆盖。索引里以**原始姓名**为主键。
- **空录音 / 过短录音**：前端应阻止提交过短录音；服务端对转码后时长
  `< minSeconds` 的音频返回 `400`。
- **超长录音**：前端到达 `maxSeconds` 自动停止录音。
- **上传中断**：请求中断或超时不得留下半截文件或索引记录。具体地：
  半截临时文件必须被删除、已创建的写流必须关闭（不得长期占用文件描述符）、
  内存缓冲必须释放，且处理流程不得永久悬挂。
  受限的资源在中断后 5 秒内应被回收；连续多次中断不得造成资源累积。
- **同名并发提交**：以最后完成的写入为准，不得损坏索引。
- **`DATA_DIR` 不可写**：启动时即报错退出，给出明确提示。
- **音频文件其实是别的东西**：ffmpeg 转码失败 → `500`，不落盘。
- **浏览器不支持 MediaRecorder / 拿不到麦克风**：前端需给出可读的提示，
  并说明"必须用 `https://` 或 `localhost` 访问"。

## 技术约束

遵循 `constitution/tech-stack.md` 与 `AGENTS.md` 的「本项目特有约束」。要点：

- Node.js 内置 `http`，不引入 Web 框架；语言用 JavaScript，不用 TypeScript。
- 前端零构建，原生 HTML/CSS/JS，直接 `<script>` 引入。
- 运行时依赖只允许 `busboy`（multipart 解析）；如需其他依赖须先说明理由。
- **录音必须关闭 `echoCancellation` / `noiseSuppression` / `autoGainControl`**。
- 口令只在服务端校验，不得出现在前端代码或 `/api/config` 响应中。
- 不引入数据库。

## 兼容性要求

- 目标浏览器：Chrome / Edge / Safari 的近期版本。录音格式需对
  `audio/webm;codecs=opus` 与 `audio/mp4`（Safari）都做兼容处理。
- 无既有数据需要兼容，`DATA_DIR` 为全新目录。
- 索引文件需带 `version` 字段，便于将来结构演进。

## 验收标准

- [ ] `npm install && npm start` 在装有 ffmpeg 的环境下能直接启动，控制台打印两个入口 URL 和数据目录
- [ ] 缺少 ffmpeg 时启动失败并打印可读的安装提示
- [ ] `ADMIN_CODE` 为默认值时启动打印醒目警告
- [ ] `GET /api/config` 返回完整的文稿、时长阈值与上传上限，**不含任何口令**
- [ ] `GET /` 与 `GET /admin.html` 可正常打开，静态资源可加载
- [ ] 员工端：口令错误被拒；口令正确后能填写姓名并进入录音界面
- [ ] 员工端：能调用麦克风录音，录完能试听、能重录，两段都录好后才能提交
- [ ] 员工端：录音请求关闭了浏览器的 `echoCancellation` / `noiseSuppression` / `autoGainControl`
- [ ] `POST /api/submit` 带正确口令与两段音频 → `200`，数据目录下出现该员工目录与两个 WAV
- [ ] 生成的 WAV 经 `ffprobe` 验证为单声道、16-bit PCM、采样率等于 `SAMPLE_RATE`
- [ ] `POST /api/submit` 口令错误 → `401`，且不产生任何文件
- [ ] `POST /api/submit` 只带一段音频 → `400`
- [ ] 同名再次提交 → 覆盖旧文件，`firstSubmittedAt` 保持不变、`updatedAt` 更新，不产生第二行
- [ ] 姓名含 `../`、`/`、控制字符等 → 不产生目录穿越，文件仍落在 `DATA_DIR/recordings/` 内
- [ ] 管理端：未登录访问 `/api/admin/submissions` → `401`
- [ ] 管理端：口令正确后可登录，列表正确列出所有已提交员工
- [ ] 管理端：试听接口支持 `Range`，返回 `206`；未登录 → `401`
- [ ] 管理端：下载接口返回 `attachment`，文件名含姓名与段落
- [ ] 服务重启后索引与录音仍可读，管理端列表不丢数据
- [ ] 前端在无麦克风权限 / 非 secure context 时给出可读提示，而不是静默失败
- [ ] `README.md` 记录的启动方式与实际一致
- [ ] 未创建根目录 `.github/`，未改动其他子项目与根目录文档以外的全站结构
