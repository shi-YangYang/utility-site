# 工具站（Utility-Site）

一个仓库，装很多个互不相干的小工具。

每个工具占据根目录下的一个文件夹，各自独立使用，互不依赖。
这份 README 是给人看的门面；仓库的规则和约定写在 [AGENTS.md](./AGENTS.md) 里。

## 工具清单

- [recording](./recording/) —— 公司内部的语音样本采集：员工在网页上录一段中文、一段英文并上传，管理员查看提交情况、试听与下载
- [deploy](./deploy/) —— 全站部署与运维：反向代理、端口分配表、部署脚本与约定（非业务工具）

新增工具后在这里补一行：`[工具名](./子项目名/) —— 一句话说明它干什么`

## 怎么用

每个工具的用法写在它自己的文件夹里。点进对应的目录，看那里的 `README.md`。

## 关于这个仓库的规则

仓库的组织方式、Agent 协作流程、每个子项目要做多重（LIGHT / FULL 两档），都写在 [AGENTS.md](./AGENTS.md) 里。那是这个仓库唯一的通用规范。

规模大一些的子项目，会在自己的文件夹里再放一份简短的 `AGENTS.md`（声明继承根规范）、以及 `constitution/`、`specs/`、`.ai/` 三套目录；小工具则只有 `README.md`。这属于子项目内部的结构，不影响你直接用工具。
