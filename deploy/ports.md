# 端口分配表

全站多个子项目并存时**按端口区分**（2026-09-16 定）：
应用端口只在服务器本机使用；需要 HTTPS 的项目由共享代理在**对外端口**上提供服务。
**先在本表登记再使用。**

## 端口划分

| 范围 | 用途 | 说明 |
|---|---|---|
| `80` / `443` | 共享代理（Caddy） | 首个项目默认对外用 `443`；`80` 留作 HTTP→HTTPS 跳转与证书用途 |
| `3000–3099` | **应用端口（本机）** | 每个子项目一个，仅服务器内部与代理访问，不对公网开放 |
| `3100–3199` | **对外 HTTPS 端口（Caddy）** | 第二个及以后需要 HTTPS 的项目，各占一个（如 `3100`） |

|---|---|---|---|---|
| 3000 | 443（共享） | recording | `recording` | 员工端 + 管理端；员工端录音要求 HTTPS |
| — | — | deploy/proxy | `caddy` | 共享反向代理本身 |
| 3001 | 3100 | *（示例，未占用）* | — | 第二个子项目的接线示例，见下方流程 |

新增子项目时：在本表补两行（应用端口 + 对外端口），并确认不冲突。

## 接入新子项目（端口区分）

1. **登记端口**：在本表选一个空闲的应用端口（3001 起）与对外端口（3100 起）。
2. **子项目自备可部署单元**：`Dockerfile`、`docker-compose.yml`（宿主端口用
   `${HOST_PORT:-xxxx}`，数据卷挂到自己的 `data/`），并在 `recording/.env` 同级的
   项目 `.env` 中管理自己的配置。
3. **需要 HTTPS 的项目**（例如会用到麦克风/摄像头）：
   - 在 `deploy/proxy/docker-compose.yml` 增加对外端口映射，例如 `- "3100:3100"`；
   - 在 `deploy/proxy/Caddyfile` 增加一段：
     ```caddy
     https://<服务器IP>:3100 {
         tls internal
         reverse_proxy host.docker.internal:3001
     }
     ```
     （`tls internal` 的证书按 IP 签发，多端口共用同一张证书，不需要重复申请。）
4. **不需要 HTTPS 的纯展示工具**：不必进代理，直接用应用端口对外
   （`http://<服务器IP>:3001`），安全组单独放行即可。
5. **安全组/防火墙**：只放行对外端口；应用端口不要对公网开放。
6. **部署**：`./deploy/scripts/deploy.sh <项目名>`；改过代理再执行一次 `deploy.sh proxy`。
7. **登记文档**：根 `README.md` 工具清单与本表同步更新。

> 更干净的替代方案（暂未采用）：让各项目加入同一个 Docker 网络、由代理按容器名
> 访问，从而不再占用宿主应用端口。需要动每个子项目的 compose，等子项目多起来再说。
